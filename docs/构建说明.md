# CookTrace 简体中文版构建说明

本文档面向要构建、分发、升级 CookTrace 简体中文版（Android APK）的维护者。业务与架构背景另见 [业务场景说明](./analysis/业务场景说明.md) 与 [技术架构文档](./analysis/技术架构文档.md)。

## 一、版本形态与本地存储架构

简体中文版以 **Android 本地模式**为默认形态：

- 全部业务数据（菜谱、食材库、烹饪日记、购物清单、分类、图片）存于**设备本机 SQLite**（`@capacitor-community/sqlite`，库名 `cooktrace_local`），不依赖任何远程服务器。
- 用户配置存于本机（localStorage / 本地设置表）。
- 首次启动向导默认引导进入本地模式；需要多人共享时仍可在「设置 → 服务器连接」配置自托管服务器（可选，不影响离线使用）。
- 运行缓存（图片缩略、导入临时文件）同样落在本机应用数据目录。

**离线可用的核心功能**：菜谱增删改查与编辑器、文件导入（JSON / HTML / 文本 / 通用 ZIP）、URL 抓取导入（经 CapacitorHttp 直连目标网站）、拍照/图片、条码扫描（ML Kit，本机识别）、食材库（含过期管理）、周计划、购物清单、烹饪模式与计时器（本地通知）、烹饪日记、本地备份（含定时自动备份）、单位换算（公制 + 市制：斤 = 500 g、两 = 50 g）。

**需要联网的功能（属预期）**：AI 助手（直连所选国产大模型 API）、URL 抓取（要访问目标网站）、在线升级检测与下载（访问 GitHub）。

## 三、在线自动升级

升级源为 GitHub 仓库 **`zhouhuan/cooktrace`** 的 Releases：

1. 应用启动后调用 GitHub `releases/latest` 接口比对 `versionName`（客户端 `src/lib/updates.js`；服务器模式另有 `server/routes/updates.js` 兜底，两处常量一致）。
2. 发现新版本后，从 Release 资产中挑选不带 wear/watch 字样的 `.apk`（`src/lib/apk-asset.js`），下载到应用数据目录 `updates/`。
3. 通过 `file-opener` 唤起系统安装器完成安装（Manifest 已声明 `REQUEST_INSTALL_PACKAGES` 与 FileProvider 路径）。
4. 升级口径为**按需整包下载**（检测到新版本才下载完整 APK），不做二进制差分；首次安装需手动装 APK。

> **签名约束**：覆盖升级要求新旧 APK 签名一致。必须先完成「四、CI 配置」中的签名初始化再对外发布任何版本，否则用户端将无法静默升级。

## 四、CI 构建（推荐路径）

本仓库已含 `.github/workflows/android.yml`，包含三个 job：

- **test**：push 时跑 `npm run i18n:check`、`npm run check:zh`、`npm test`（Node 22）。
- **release**：push tag `v*` 或手动触发（非 main 分支）时：`npm run build` → `npx cap sync android` → JDK 21 + `gradlew assembleRelease` → APK 附到 GitHub Release（tag 触发）或 Artifacts（手动触发）。
- **init-signing**：在 main 分支手动触发，生成 release 密钥库（一次性）。

### 首次配置步骤

1. **初始化签名**（一次性）：在仓库 Actions 页手动运行 `android` 工作流（main 分支），会执行 init-signing job。把输出中的：
   - base64 字符串 → 存为 secret `KEYSTORE_BASE64`
   - 生成的口令 → 存为 `KEYSTORE_PASSWORD` 与 `KEY_PASSWORD`
   - 别名固定为 `cooktrace` → 存为 `KEY_ALIAS`
   - 同时把 Artifacts 里的 `cooktrace-release.keystore` 文件下载并离线备份（丢失后无法继续对已装用户推送更新）。
2. **发版**：修改 `android/app/build.gradle` 中 `versionName` / `versionCode`（递增），提交并打 tag（如 `v1.5.1`）推送。CI 自动出包并把 `cooktrace-v<版本>.apk` 附到 Release。
3. 用户端在旧版本内即可检测到新 Release 并完成下载安装（见第三节）。

## 五、本地构建（备选路径）

如需在本机出包（与 CI 产物等价）：

1. 安装 JDK 21（Temurin）、Android SDK（platform 36 / build-tools，`ANDROID_HOME` 指向 SDK 目录）、Node 20+（建议 22）。
2. 把签名密钥库放入 `android/app/cooktrace-release.keystore`，并创建 `android/keystore.properties`（storeFile / storePassword / keyAlias / keyPassword，均被 gitignore）。
3. 执行：

```bash
npm ci
npm run android:apk:release
# 产物：android/app/build/outputs/apk/release/app-release.apk
```

调试包：`npm run android:apk:debug`（无需签名配置）。

## 六、离线功能验收清单（飞行模式逐项）

安装 APK 后开启飞行模式，逐项验证：

- [ ] 新建 / 编辑 / 删除菜谱，编辑器内添加食材、步骤、计时器
- [ ] 从文件导入：JSON、HTML、文本，以及通用 ZIP 批量导入
- [ ] 拍照或从相册选图作为菜谱图 / 步骤图
- [ ] 条码扫描入库（ML Kit 本机识别；商品名匹配 OpenFoodFacts 需联网，属预期）
- [ ] 食材库：增删改、库存数量、过期日期
- [ ] 一周菜单（Build My Week）生成与调整
- [ ] 由周计划生成购物清单；按份数缩放；手动增删条目
- [ ] 烹饪模式：步骤计时器（本地通知响铃）、屏幕常亮、用量换算（含斤/两）
- [ ] 烹饪日记：记录已烹饪 / 计划烹饪
- [ ] 本地备份导出与恢复（JSON 快照含图片）
- [ ] 重启应用后以上数据全部保留

## 七、本地化自查

- `npm run check:zh`：键完整性 / 插值 / 拉丁白名单三项全绿。
- 界面走查：设置（含 AI、区域与单位、服务器连接）、向导、菜谱编辑器、购物清单、烹饪模式、日记各页无白名单外英文。
- 服务端报错经客户端 `src/lib/error-zh.js` 映射为中文；未覆盖的报错显示按状态码分级的中文通用提示。

## 八、安装与卸载

- 安装：允许「未知来源/安装未知应用」后打开 APK 安装；覆盖升级需同一签名（见第三节）。
- 卸载：系统设置中卸载即清除全部本地数据（SQLite、图片、缓存均在本机，无云端残留）。
