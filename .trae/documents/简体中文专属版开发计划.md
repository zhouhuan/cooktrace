# CookTrace 简体中文专属版（Android 本地版）开发计划

## 概要

在现有 CookTrace 仓库（工作区内直接修改，不建分支）基础上，产出一个简体中文专属版：
- 界面纯中文（品牌名 CookTrace、DeepSeek、Kimi、GLM、GitHub 等按用户决定保留英文；g/kg/ml/°C 等国际标准计量符号视为"标准符号"允许保留）
- Android 本地模式（本机 SQLite）为默认形态，核心功能完全离线可用
- 单位体系改为公制 + 市制（斤/两/汤匙/茶匙）
- AI 助手换成国产厂商（深度求索 DeepSeek、月之暗面 Kimi、智谱 GLM、通义千问、豆包，全部 OpenAI 兼容）
- 在线升级指向 `https://github.com/zhouhuan/cooktrace`
- 用 GitHub Actions 云端出 APK（本机无 JDK 21/Android SDK，Node 14 过旧）

## 实施内容

### 1. 中文语言包与界面纯中文化

1. **新建 `src/i18n/zh.json`**（最大工作量，约 3524 键）。执行方式：把 en.json 按顶层命名空间切成若干块（每块约 400-600 键），并行交给子代理翻译，硬性规则：保持 JSON 结构与键名不变；`{xxx}` 插值、`@:.key` 链接、HTML 标签原样保留；品牌白名单（CookTrace、DeepSeek、Kimi、GLM、Qwen、Doubao、GitHub、OpenAI）保留英文；单位缩写（g、kg、ml、l、°C、kcal、kJ）保留。最后合并并用脚本校验（见第 7 步）。
2. **注册并锁定中文**：`src/i18n/index.js` — `AVAILABLE_LOCALES` 只留 `zh`；`fallbackLocale: 'zh'`；`pickInitialLocale()` 直接返回 `'zh'`。
3. **time-words**：`src/lib/time-words/time-words.json` 增加 zh 词条（"刚刚/n 分钟前/昨天…"），核对 `src/lib/time-words/` 内引用语言列表的代码与测试。
4. **默认值改中文习惯**（`src/stores/settings.js` + `server/routes/settings.js` 的 USER_PREFS 默认）：`language:'zh'`、`timeFormat:'24h'`、`dateFormat` 改为适合 zh 的格式、`measurementSystem:'metric'`；周起始设为周一（若存在 weekStart 设置）。
5. **泄漏点修复**：
   - `index.html`：`lang="zh-CN"`，标题改中文（如"CookTrace · 厨房好帮手"）；`public/offline.html` 全文中文。
   - `vite.config.js` PWA manifest：name/short_name/description/快捷方式（购物清单、扫码入库）中文化。
   - `android/app/src/main/res/values/strings.xml`：快捷方式等文案中文（应用名保留 CookTrace）。
   - `server/db.js` 种子分类 → 中文（早餐/午餐/晚餐/主菜/配菜/汤品/沙拉/小吃/甜点/烘焙/酱料/饮品/夜宵 13 个对应替换）；核对 `src/lib/db-native.js` 是否有同样种子，一并改。
   - **服务端错误消息**：不改几百处 `res.json`，在客户端 `src/lib/api.js` 抛错处加一层 `src/lib/error-zh.js` 映射表（覆盖高频报错：未登录、无权限、重复、校验失败等 30-50 条）+ 未命中时回退通用中文提示"操作失败，请稍后重试"。
   - `server/email.js`、`server/lib/push-notify.js`：模板文案翻译为中文（这两个文件文案集中、量可控）。
   - `src/components/ai/Trace.svelte` 系统提示词重写为中文并明确"始终用简体中文回答"；`FileImportDialog.svelte` 等硬编码英文提示改走 i18n 键。
   - `src/lib/off.js`：`offSearchLanguage` 默认改 `'zh'`（OpenFoodFacts 有中文商品名）；USDA 数据源保留（用户自选），在设置里加中文说明。
   - placeholder 类（`you@example.com` 等）改为中文示例或泛化提示（"请输入邮箱"）；密码强度 zxcvbn 的英文反馈改为通用中文文案包装。

### 2. 公制 + 市制单位

1. `src/lib/units.js`：所有单位补中文名（full 字段中文或新增 zh 名）：美制单位也给中文全名（茶匙/汤匙/杯/液量盎司/磅/加仑…），缩写（存储值）不变以保证旧数据兼容；**新增市制组**：斤（500g）、两（50g）、汤匙（15ml）、茶匙（5ml）；分组标签（体积—公制 / 重量—公制 / 市制 / 计数）中文化，公制+市制组排前。
2. 换算表：`src/lib/quantity.js` 与 `server/lib/quantity.js` **同步**在 `WEIGHT_TO_G`/`VOLUME_TO_ML`/`UNIT_VARIANTS` 加入斤/两/汤匙/茶匙（含中文别名归一化：斤=500g、两=50g、汤匙≈15ml、茶匙≈5ml；市制显示用小数不用分数）。
3. `src/components/ui/UnitPicker.svelte`：分组标签走 i18n；metric 模式下公制+市制优先展示。
4. `measurementSystem` 默认 'metric'（第 1 步已含）；能量单位默认 kcal（已是）。

### 3. 国产 AI 服务

1. `src/lib/aiChat.js` `AI_PROVIDERS`/`AI_MODELS`：移除 claude/openai/gemini，新增（均 OpenAI 兼容，baseURL 执行时以各家官方文档核对为准）：
   - DeepSeek：`https://api.deepseek.com`（模型 deepseek-chat / deepseek-reasoner）
   - Kimi（月之暗面）：`https://api.moonshot.cn/v1`（moonshot 系模型）
   - 智谱 GLM：`https://open.bigmodel.cn/api/paas/v4`（glm-4 系列）
   - 通义千问：`https://dashscope.aliyuncs.com/compatible-mode/v1`（qwen 系列）
   - 豆包：`https://ark.cn-beijing.volces.com/api/v3`（方舟端点，模型 ID 需用户填）
   - 保留 `custom`（OpenAI 兼容自定义地址）
2. 服务端：`server/ai.js`/`server/routes/ai.js` 的 provider 枚举与 `server/lib/ai-models.js` 同步这批 id（底层都走 `_callOpenAI`）。
3. `src/components/settings/SettingsTrace.svelte`：下拉与说明中文化（品牌名保留英文，如"DeepSeek（深度求索）"）。
4. 本地模式说明：AI 属在线能力（直连厂商 API），核心功能离线不受影响——写入构建说明。

### 4. 在线自动升级（GitHub: zhouhuan/cooktrace）

1. `src/lib/updates.js`：`GH_OWNER='zhouhuan'`、`GH_REPO='cooktrace'`。
2. `server/routes/updates.js`：`GH_REPO_URL='https://api.github.com/repos/zhouhuan/cooktrace'`。
3. 现有链路（版本检测 releases/latest → `pickApkAsset` 挑非手表 APK → 下载到 Data/updates → 系统安装器）不改逻辑，只把相关 UI 文案纳入 zh.json 并人工走查一遍调用点。
4. **口径说明（假设）**："增量下载"按业界惯例实现为**检测到新版本才按需下载完整升级包**，不做二进制差分包；首次安装仍需手动装 APK。

### 5. 本地存储形态收尾

1. `src/routes/NativeSetup.svelte` 启动向导：默认引导进入本地模式，文案中文化；服务器连接保留为可选项（高级）。
2. 本地备份（`src/lib/local-backup.js`）与定时备份沿用，确认中文数据/文件名正常。
3. 不新建存储架构——本地 SQLite 模式已满足"数据全部在本机"；此结论写入构建说明的架构章节。

### 6. 字体与视觉规范

1. 全局样式（`src/app.css` 或等价入口）增加中文字体栈：`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Noto Sans SC", "Microsoft YaHei", sans-serif`。
2. 布局/交互不做重设计（现有移动端布局、底部弹层、手势已是国内主流样式），仅通过默认值（24 小时制、公制、周一始、中文日期格式）完成习惯适配。

### 7. 校验脚本与测试

1. 新增 `scripts/check-zh.js`（Node 内置能力即可运行）：
   - zh.json 可解析、键集合与 en.json 完全一致、每键 `{xxx}` 插值名与 en.json 相同；
   - zh 值中不允许出现白名单以外的拉丁字母连续串（白名单：品牌名、单位符号、URL、HTML 标签、i18n 语法）。
2. 跑现有测试：优先尝试 fnm/nvm 装 Node 22 后执行 `npm test`（重点 `scripts/quantity*.test.js` 双份一致性、i18n 完整性检查、field-sync 一致性）；装不上则全部依赖 CI 跑（见第 8 步，CI 含 test job）。
3. UI 走查（尽力而为）：若本机能起 Node 22 dev server，用浏览器代理抽查主要页面的中文渲染与无外文残留；否则走查推迟到 APK 产物，写入交付清单由用户验收。

### 8. GitHub Actions 出包（`.github/workflows/android.yml`）

1. **test job**（push 触发）：Node 22 → `npm ci` → i18n 检查 + `npm test`。
2. **release job**（push tag `v*` 或手动触发）：
   - Node 22 → `npm run build` → `npx cap sync android`
   - setup-java 21（temurin）→ `android/gradlew assembleRelease`
   - 签名：secrets `KEYSTORE_BASE64`/`KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD` → 解码写 `android/keystore.properties` + keystore 文件（build.gradle 已支持）
   - `softprops/action-gh-release` 上传 APK（非手表）到 Release，资产名含版本号
3. **init-signing job**（手动触发一次性）：生成 release keystore，把 base64 与口令输出到 Actions 日志（提示用户存为 secrets 并妥善备份），确保后续签名稳定（否则签名不一致会阻断覆盖升级）。
4. 版本号：`android/app/build.gradle` 的 versionName/versionCode 手动递增，打 tag 触发发布。

## 关键假设与决策

1. 品牌名保留英文是用户明确选择；单位符号 g/kg/ml 等按"标准符号"豁免。
2. applicationId 保持 `com.cooktrace.app` 不变；本版即独立分发版。
3. 直接在当前工作区修改（含少量服务端文件以保证服务器模式可用），由用户自行提交并推送到 `zhouhuan/cooktrace` 触发 CI 出包。
4. 升级为"整包按需下载"，无二进制差分。
5. AI、URL 抓取、在线升级、GitHub API 本身需要网络，属预期；"全部核心功能离线可用"指菜谱/食材库/日记/购物清单/烹饪/备份/导入导出。
6. USDA 数据源保留但默认引导用 OpenFoodFacts（zh 语言检索）。
7. 本机无构建工具链：本地只做静态校验与（若可行）dev server 走查，正式产物全部由 CI 出。
